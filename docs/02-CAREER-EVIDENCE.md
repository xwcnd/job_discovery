# Build your personal evidence base (private)

The system's accuracy depends on the **full factual record**, not on fashionable resume keywords. A short, polished resume can hide relevant work and lead to both false negatives and false positives.

## Minimum input

**Required to screen responsibly:**
- **Complete/base CV:** full employment history, employers, role titles, month/year dates, responsibilities, education, skills, certifications, major results and locations, even if much longer than a resume sent to employers.
- **Targeting preferences:** desired functions and industries, countries/cities, remote/on-site/relocation, salary benchmark and currency, languages, travel availability and country-specific work authorization. Use `UNKNOWN` rather than a guessed answer.
- **One exact job description** for the first test.

**Strongly recommended:**
- **Detailed project portfolio** showing each project's organization/time frame, objective, technical object, personal role, personally performed tasks, team vs individual outcomes, methods/tools, systems, stakeholders, measured results, evidence confidence and constraints.
- **Underlying records** (non-confidential project descriptions, certificates, patent/publication references, factual performance reports) only when legitimately shareable.
- **Prior corrections** that reconcile out-of-date titles, conflicting metrics, or methods named in a summary without direct project evidence.

## Source precedence

1. Explicitly designated current full/base CV.
2. Original detailed project list and source project records.
3. Other factual career records supplied by user.
4. First-person, vacancy-specific corrections clearly anchored to role/project/time.
5. Any tailored/generated CV, cover letter, application answer or prior score is derivative; use only to understand past presentation, never as superior proof.

Source documents can conflict; record the contradiction instead of quietly preferring the version with the strongest claim. The **user can clarify** a discrepancy; make the correction specific and versioned. A tool name in a skills list may establish familiarity, but not independent design responsibility or years of daily use.

## Project evidence card (copy privately for important projects)

```text
Project or workstream: [name]
Company/organization and period: [employer, month/year]
What the project was trying to achieve: [purpose]
Role: [formal title / project role; distinction]
I personally: [actions, equipment, methods, decisions, artifacts]
I led/coordinated: [exact scope, team/vendor distinction]
I supported or observed: [scope; do not upgrade]
The team/company achieved: [outcome; attribution]
My directly measured outcome: [metric and method, if substantiated]
Technical object / relevant standards: [exact technologies and environment]
Documentation produced: [requirements, test plans, acceptance, SOP, etc.]
Unknown or restricted details: [no invented fill]
Evidence source and confidence: [document/version, or firsthand statement]
```

**Disaggregate specialist depth.** Examples: using measurement instruments != developing validated production test methods; integrating purchased hardware modules != owning core-system design, modeling and tolerances; managing a supplier != personally engineering the supplied equipment; participating in a project != owning its budget and delivery. Similar distinctions apply in every technical field.

## Distinguish candidate configuration from employer facts

- Desired salary is a *candidate preference*, not an employer-imposed minimum. If employer salary is hourly, avoid assuming guaranteed annual pay without hours.
- Relocation preference in one country does not establish a visa/right-to-work in another.
- Ability to learn a new tool is positive for career decisions, **not evidence of prior professional experience**.
- Self-assessed language proficiency differs from a verified official score; do not invent tests or certificates.
- Formal method labels (e.g. named continuous-improvement methodologies) differ from using similar practices without that name; ask how it was actually applied.

## Sensitive materials

Use a private Project and private Drive for your career records. Avoid including full home addresses, identity numbers, passwords, confidential designs, customer contracts or protected personal information when they are not needed for fit screening. Redact unnecessary content from shareable summaries. Do not place filled resumes or private source links in this public repository.

## Maintenance

On meaningful career updates, designate the newest authoritative base CV *explicitly*, update project evidence and source manifest, document any superseded claim, and re-evaluate only affected existing scored roles or relevant future screen rules. Never assume a date stamp on a derivative copy makes it the primary CV.
