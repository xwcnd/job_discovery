# From discovered vacancy to truthful application

The discovery system does **not** automatically apply to jobs. Once a user selects a vacancy, use that exact current JD as the controlling vacancy source and the complete private career evidence as the controlling candidate source.

**Reusable separate-chat prompt:** [Vacancy Application Workflow](../prompts/VACANCY_APPLICATION_WORKFLOW.md). For a guided first-time setup, follow [Stage 2: One vacancy per chat](12-VACANCY-APPLICATIONS.md). This prompt is used *after* discovery; it is not the daily email-monitoring prompt. It uses the candidate's own private identity/contact details, and requires explicit approval before CV drafting and again before a cover letter.

## Vacancy review

- Enumerate exact mandatory and preferred bullets, seniority, working arrangements, travel, language, education/certification, authorization, and posting/apply-state uncertainty.
- Show an evidence map: **STRONG DIRECT MATCH / PARTIAL OR TRANSFERABLE / WEAK / NO EVIDENCE**. Distinguish an employer hard requirement from a practical gap in the actual role's core function.
- Explain concrete, material mismatches. If the user wishes to apply with a known gap, support truthful preparation without relabeling the job as verified eligible.

## Tailored CV

Start from complete primary sources. Reassess the **whole** document: order, summary, roles, projects, technical detail, outcomes, omitted evidence, unnecessary sections and space allocation. Preserve employers, dates, responsibilities, technology level, attribution and supported metrics. The correct priority is more relevant direct evidence and clear ATS-readable terms, not keyword stuffing or unsupported self-praise. Compare the final CV to original base CV, detailed portfolio and JD to detect important losses or regressions.

**Candidate-position fit** remains unchanged by rewriting. A separate **document-quality** review can evaluate whether evidence is visible, accurate, easy to parse and complete. Use native Google Docs where requested and available; do not post private resumes to public GitHub.

## Cover letter

Write a vacancy-specific concise letter that complements, rather than restates, the CV. Connect 2–4 substantiated accomplishments/contributions to the employer's actual work. Explain motivation only when plausible and grounded; avoid invented personal admiration or domain exposure. Keep a factual distinction between individual contributions and company/project results. Don't assume a required cover letter is optional if the employer specifies one.

## ATS and forms

Identify the actual platform where possible. Review imported/autofilled fields against the final CV:

- Correct name, capitalization, email, phone, address/location and dates.
- Correct employer/title mapping, position chronology, current employment flag, overlapping part-time roles, and education level.
- No duplicate work entries or wrong field assignments.
- Accurate work authorization, travel, language, licenses and years/depth of experience.
- Consistent salary currency, basis (hourly/annual), availability and current work status.
- Accurate application answers to mandatory Yes/No questions: never turn `No` into `Yes` to pass a gate.

In Workday and other systems, do not trust resume parsing blindly. A warning may be a formatting issue or a real hard requirement; inspect the exact content and, where necessary, current official platform guidance. Do not falsify personal identity or qualifications merely to silence a warning.

## Submission boundary

Never click a final submit button, send a recruiter message, write a contact email, or share documents externally unless the user actually authorizes that action. A saved draft is not a sent application.
